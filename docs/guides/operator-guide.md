# Operator handbook: Mission Control, Forge and terminal
<!-- docs-section: overview -->

**Language / 语言:** [English](operator-guide.md) · [简体中文](../zh-CN/guides/operator-guide.md)

This guide covers the **current** v1.4 developer workbench without pretending that v1.4 Stable or real environment qualification is complete. Use in-product `?` for the authoritative keymap and `--help` for CLI behavior. Read [team quickstart](../team-quickstart.md) first.

## First session and target
<!-- docs-section: first -->

~~~bash
codex-tui --version
codex-tui doctor compat
codex-tui doctor codex
codex-tui
~~~

The default workflow is deliberately short: `Space` jumps to the next Needs You item, `Enter` opens the selected work, `/` searches, and `1–9` switches bound tasks. Press `?` to show full keyboard help; on a narrow SSH terminal `↑/↓` or `j/k` scroll entries, `PgUp/PgDn` move three entries, `Home/End` reach the first/last item, and `Esc` closes without navigating behind the overlay.

**Pointer limitation:** mouse click and wheel events are not handled. To avoid swallowing normal terminal selection/scroll behavior, the app no longer requests mouse capture. The legacy `[ui].mouse` setting is still parsed but ignored. Do not treat `mouse = true` as enabling navigation.

Default target is local `codex app-server --listen stdio://`. Named targets are configured in local TOML; one invocation can use `codex-tui --target NAME`. Non-loopback plaintext `ws://` targets are rejected even without a configured token; use `wss://` or loopback through an SSH tunnel. Loopback IPv4, IPv6 and `localhost` remain permitted for local development. A dead or incompatible backend is **not** silently replaced by fake data; distinguish `--fake` fixture mode from real sessions. Read [Remote Target design](../implementation/v1.3-remote-app-server-targets.md).

**First connection failed:** after correcting the transient backend problem, press an unmodified, single `F5` in empty Mission Control with no editor, help, confirmation or focused Terminal Drawer. This retries the same resolved target with at most one attempt in flight; there is no automatic retry timer. Drafts and local operator state are retained. Once a connection has been installed, F5 cannot reconnect an established session, even after a later disconnect. It never replays prompts or approvals, and does not reload target configuration; correct invalid configuration and restart explicitly.

`doctor` prints a single-line, terminal-safe presentation of external paths, branches, host names, diagnostics and error strings; ANSI controls and Unicode bidi overrides become visible replacement characters. Original Codex/Git/Forge data is not rewritten.

Human-readable `headless` text output escapes *individual* untrusted fields while retaining tab-delimited rows. `--json` remains a machine-readable serialization of the original snapshot, not display-normalized content.

`doctor compat` escapes unsafe control characters in human-readable tool versions and diagnostic facts. `doctor compat --json` preserves the original evidence and schema.

CLI usage error, support-bundle path and `doctor` startup failure messages also sanitize unsafe terminal-control characters at their final presentation boundary. The normal help text and original file paths remain unchanged.

## Navigate work and attention
<!-- docs-section: daily -->

In Thread view, `PageUp`/`PageDown` scroll the displayed lines of a message, including long paragraphs and code blocks. `Home` moves to the start of loaded history; another `PageUp` there requests an older page. `End` resumes following the newest content. Manual scrolling pauses follow and retains the reading position when messages arrive, older pages load or the terminal is resized. A pending request remains visible while the remaining rows can still browse history.

If a refreshed recent page no longer contains the item you are reading, Thread retains a local snapshot of that older history while live turn status continues to update. The paused-reading label identifies this snapshot; `End` returns to the latest history and releases it, and leaving Thread also releases it.

With a pending request and no text editor active, press `d` in Thread view to read its command, working directory and permission details. In this local detail view, `PageUp`/`PageDown` and `↑`/`↓` scroll, `Home`/`End` move to either end, and `Esc` returns without submitting or cancelling the request. Resolving or replacing the request invalidates its detail view; browsing sends no App Server request. Unrecognized permission fields remain marked as hidden, with acceptance disabled.

Opening a thread or its queue acquires an App Server subscription on the active connection. Server-loaded inventory and history reads alone do not establish that subscription. The connection releases it when the last history, queue or pending-request owner leaves; active work and actionable requests retain their existing ownership. A rejected or uncertain subscription is reported instead of silently replaying writes. The pinned protocol baseline has been reviewed through Codex 0.164.0 using tagged source and synthetic parser replay; actual account qualification remains separate. Additive upstream read-state fields and notifications do not synchronize local unread/acknowledge state. Image-generation items keep their generic item presentation for both inline results and file references; the client does not fetch those image files. See the [retained compatibility assessment](../../tests/fixtures/protocol/stable-0.164.0/assessment.json).

Mission Control puts actionable attention first, then pinned threads and recent activity, with deterministic ID tie-breaking. It preserves the existing recent-thread window plus pins and attention exceptions, rather than expanding into all history. Snooze suppresses attention elevation while retaining pins; acknowledging an item does not hide a live approval, input request or error. Initial loading selects the first displayed thread; later refreshes retain the selected thread ID while it remains visible. Compact terminals show the attention reason in the runtime column, while ordinary rows retain their runtime state.

Quick prompt opens the selected thread's visible composer from Mission Control, Review, Workspace. `Esc` leaves composition while retaining the draft; another `Esc` returns to the originating page. Navigating to another thread clears that temporary return route.

Registry attention also includes already observed Goal blocking, usage/budget limits, failed pipelines, requested changes and worktree conflicts. Registry displays one row per session and truncate long titles or workspace labels to the terminal width, so navigation keeps the selection visible.

Observed idle/Goal-completion transitions, approvals/input requests, errors, usage/budget limits, pipeline failures and review events can appear in a one-line header when the terminal has room, including with `[notifications].mode = "off"`. The `! open` action appears at the **start** of the alert line, before a potentially long task title, and `Unlocated` is shown instead when no Codex thread exists. Press `!` to jump to the related live Codex thread and return with `Esc` (one-level navigation); terminals that report the physical shifted digit as `Shift+1` instead of `!` are also handled. Modified digit keys do not activate hot slots. Approval and destructive confirmation hotkeys require an unmodified key press (not a held-key repeat); Ctrl+C keeps its existing interrupt/cancel semantics. Elapsed alerts are rejected at the action boundary, without trusting the periodic UI expiry sweep. Help (`?`) is modal: `Esc` or `?` closes it rather than navigating behind the visible overlay. This 20-second, memory-only recent-event indication is not a new task authority or a guarantee that external delivery succeeded. Events without a live thread require inspection of the authoritative source; no nonexistent thread is opened. The header does not consume space while editors, approval details, the help screen, command palette, confirmation dialogs, or the terminal drawer's focused PTY are active. While a foreground modal is open, `!` does not navigate or consume the observed alert.

**Idle is not success:** `Now idle; check result` only reports a transition from working/waiting to idle. It does not prove a turn succeeded or a task passed acceptance. `Goal completed` requires an observed Goal completion transition, which is still not delivery acceptance. Alerts also cover observed system errors, usage limits and budget limits; unavailable upstream facts are not invented.

Use `=` then `1–9` to bind the selected Codex thread in its connected Target/CODEX_HOME scope. Historical unscoped shortcuts remain in the original store for inspection but cannot navigate; explicitly rebind in the verified scope. Notes, snoozes and new bookmarks are likewise scoped; historical unscoped notes/snoozes/completion flags never label or suppress a real session. Note and snooze editors retain their input until the SQLite receipt, and reject a changed or disconnected scope. A disconnected or changed scope rejects binding and jumps. No historical row is migrated or overwritten. In Registry, Thread, Review, Workspace, `1–9` opens the bound Codex thread directly. For Codex threads, one `Esc` returns to the originating work surface; this is one-level navigation rather than a separate history stack. The current thread does not reload when reselected. The thread target resolves through the existing identity index, not a full scan of large inventories. An unavailable target reports a notice and does not silently open another thread. Editor/confirmation modes and focused Terminal Drawer retain their keyboard ownership. Hot slots do not start or schedule any work.

Select with `j/k`, open with Enter, filter via `/`, use `Ctrl+K` for commands, and `?` for the live keymap. From Mission Control, `r` opens Review and `w` opens Workspace for the selected thread. These routes expose existing delivery context. Attention remains an observation, never a second team task authority.

Headless `threads`, `work`, `status`, `attention` and `board` use the configured active Codex target or `--target NAME`; each invocation is a single-target snapshot unless `threads --all-targets --query TEXT` is explicitly requested. In Mission Control, `Ctrl+K` → **Search all targets** provides the same bounded read-only metadata discovery with progressive Partial results. Their source fields identify target and transport, and planning views identify the local store as shared across targets. Operator aliases, pins and confirmation preferences are scoped to the configured target and observed Codex home; unscoped legacy preferences are quarantined. Old planning metadata may still use bare thread IDs and is not cross-target authority. Forge instead reads the current directory; Worktrees reads the shared local cache. See the [CLI scope and failure contract](cli-reference.md#read-only-headless-commands).

Use native Codex CLI to manage queued submissions. The Lite candidate no longer opens or edits a separate Thread Queue or requests its inventory. Existing conversation watches and pending interactive requests remain independent.

Use native Codex CLI to create, edit, pause, resume or clear Goals. In Thread, `g` (or the palette's Refresh observed Goal) only reads the selected thread's current Goal; observed limits, blocking and completion still inform Attention. No Goal write is issued by codex-tui.

Interactive bulk Board edits, Scratch creation/edit/state/delete and Saved View creation/edit/delete are retired in the Lite candidate. The interactive Board and Scratch navigation entries are retired, and the TUI no longer starts the historical projection worker. Historical planning records remain available to explicit read-only headless inspection, `doctor store`, and backup/recovery tests. Existing offline diagnostic fixtures do not represent live TUI behavior. Create or update real work in its original authority, and link the native session to its work reference. Session note, snooze and bookmark routes remain; no existing SQLite records are removed or rewritten by the retirement.

Mission Control search, session details, bookmark labels and native notification routing no longer depend on Board cards. `/` matches session metadata, current checkout/Forge observations and retained local notes; scoped fields are `thread:`, `cwd:`, `project:`, `goal:`, `forge:`, `branch:`, `worktree:`, `runtime:` and `note:`. Former `card:`, `work:`, `link:`, `related:`, `stage:` and `tag:` qualifiers are retired; use the original work authority or `workref` for actual work associations. Historical data is retained, not silently reinterpreted as current native status.

Mission Control and native session alerts derive attention directly from current Codex Goal, Git and Forge observations, rather than waiting for Board cards. The old snooze/completion preferences are indexed read-only during migration; they do not authorize writes. A snooze can defer soft attention, but never suppresses live approvals, input requests or system errors in Mission Control or native notifications.

Search and Saved Views are local organization; unseen upstream history is not fabricated. Full-history search uses a short-lived isolated Codex App Server connection so it cannot monopolize the live approval/session actor; only one search runs at once, newer requests cancel older searches, and an overall 12-second deadline fails visibly. Partial per-thread occurrences never claim complete history. When an awaited RPC yields to an inbound approval request, the live actor drains that queued request before accepting competing commands or scheduled probes; an interrupted RPC remains outcome-unknown and is not blindly replayed. Short local-index queries treat `%`, `_` and backslash as literal characters rather than SQLite wildcard patterns. Use a concrete repository/cwd to distinguish foreign Windows paths from Ubuntu-local Codex threads. Clearing an upstream project or thread title temporarily projects the safe cwd/ID before a coalesced authoritative refresh; unarchiving requests the same bounded refresh without inventing missing threads. App Server Git origins are normalized to credential-free host/repository identity; malformed origins fall back to cwd, never into search, Headless or display. A weekly advisory compares the pinned protocol fixture with the official Codex stable release; newer upstream metadata requires review and never counts as authenticated L3 qualification.

Local transcript search matches cached user/assistant **message bodies** for both short LIKE queries and longer FTS queries. Thread titles remain searchable through the global metadata search. Missing FTS support uses the same body-only field scope; local results remain an incomplete cache, not full-history authority.

The Review `e` external-editor action now requires a current Git worktree identity matching the selected thread and review. Git status paths resolve from the worktree root (not a nested thread cwd); absolute paths, parent traversal, missing targets and symlinks resolving outside the worktree are rejected before launching an editor. Refresh Review and Git context if the identity is stale. No source path or Git state is modified.

Review external browser links require an unambiguous HTTP(S) host without embedded credentials, control characters, whitespace or backslash normalization. Invalid provider links fail before browser launch; valid GitLab/GitHub URLs are passed through unchanged.

**External open over SSH:** the editor/browser command runs on the host running the TUI, not automatically on the Windows client. When `SSH_TTY` or `SSH_CONNECTION` is present and no explicit adapter is configured, the default graphical launch is refused before process creation; use the displayed target manually or configure `CODEX_TUI_EDITOR` / `CODEX_TUI_BROWSER` as a single executable adapter. Path and URL validation still apply. Starting a process is not proof that its window opened or that it later exited successfully; no Windows bridge, guaranteed full-target copy window or final external-program receipt is provided.

## Repository and delivery context
<!-- docs-section: forge -->

Switch to a repository with a configured Git remote and run `codex-tui doctor git` and `codex-tui doctor forge`. Internal GitLab uses authenticated `glab`; GitHub uses `gh`. A partial GitLab/GitHub read failure keeps healthy capabilities visible but marks Forge data incomplete; failure of all core read endpoints is unavailable, not a fresh empty result. Headless Forge returns a degraded exit code when any core capability is missing.

Review details are tied to the current repository, branch, change-request ID and observed head revision. A branch or head change invalidates mismatched cached details and late responses. Opening Review refreshes expired or failed details against the existing freshness TTL. Overview reads follow Git context observation events, limited to the recent Registry window, selected/active sessions and cached pinned/Attention sessions; there is no separate 15-second global Forge poll. Historical observations remain cached and age normally until revisited.

HTTP(S) Git remotes retain a nondefault port in the provider authority, such as `gitlab.example:8443`; authenticate that authority in `glab`. An SSH transport port, such as `:2222`, is not an API port. If SSH and API endpoints differ, keep their mapping in the provider CLI configuration.

Forge overview lists are bounded recent first pages (20 items per capability). Raw API page saturation is preserved before GitHub's Issues endpoint filters out pull requests. A current-branch CR or Pipeline not found in that snapshot is not proof of absence; check the native provider. GitHub fork PRs and workflows are projected with qualified source identity, and missing head repository provenance is not treated as a local-branch failure. GitLab cross-project MRs likewise preserve their source identity. Forge create/comment/approve/merge and automatic mutation recovery are retired from the Lite runtime. Use the authoritative provider or CLI; retained historical receipts, including Pending/OutcomeUnknown records, are not erased or replayed. See [provider evidence](../qualification/provider.md).

Managed Worktree creation, adoption, removal and branch deletion are retired from the Lite runtime. Use native Git/Codex tools and verify actual repository, worktree and active-session scope before destructive actions. No existing worktree directory, branch, managed record or receipt is deleted by this retirement. Resolve old uncertain outcomes against Git before taking another action. The read-only `worktree list` reports historical locally recorded inventory, not authoritative live Git inventory.

## Local language and accessibility
<!-- docs-section: language -->

Set `[ui].language = "en"` or `"zh-CN"`, or leave `"auto"` for locale detection. `presentation = "quiet"` coalesces background redraws; `"screen-reader"` uses longer background intervals while keeping direct input responsive. `[notifications].mode` defaults `"off"`, which disables only external delivery; in-app recent-event hints and accurate jumps remain available. `screen-reader` changes redraw cadence, not certified assistive-technology support. Alert bursts within 75 ms are grouped into one bell/toast with the highest priority reason and a count of other updates; the underlying attention and edge-tracking remain unchanged. Over SSH, `"os"` uses the client TTY bell instead of incorrectly sending a desktop notification to the server's graphical session. Windows Terminal users can enable `"bellStyle": "all"` in the relevant SSH profile and test `printf '\a'` on Ubuntu; this enables terminal sound/taskbar attention but does **not** install a Windows notification bridge. The TUI must remain running with a live connection; socket closure, terminal emulators and tmux can affect delivery. Desktop notification subjects are escaped and truncated for display only; Linux OS notifications pass dynamic text after the `notify-send --` option terminator. Enabled external notifications use a bounded dispatcher plus a 128-event pending retry queue, drained by the normal UI loop; saturation reports the number of events not queued and directs the operator to Needs You rather than claiming lossless delivery. Original work item titles and notification tracking remain unchanged. These are local preferences, not team policy or synchronization.

The retained historical worktree inventory and operation receipts are audit records. Do not treat them as a live recovery or execution route.

Terminal Drawer output draining is cooperative: at most 16 queued PTY events are parsed per main-loop iteration, leaving burst output in the existing 64-slot FIFO rather than starving keyboard, rendering and reconciliation during a noisy child process. A delayed PTY Ready event cannot revert an earlier requested terminal resize or desynchronize the VT parser dimensions. The PTY queue remains bounded; this hosted regression is not a replacement for real controlling-TTY qualification.

## Windows SSH Ubuntu and Terminal Drawer
<!-- docs-section: ssh -->

When using a Windows SSH client to operate an Ubuntu host, the TUI runs on **Ubuntu**; the target tty, filesystem, Codex CLI, config and spawned shell must all be resolved there. `Alt+T` switches focus **both ways** (no function-row key) between the app (including Mission Control) and Terminal Drawer without restarting the shell/PTY. `t` opens or focuses the Drawer, `T` closes it, and `Ctrl+]` remains the fallback to return from a focused terminal. Modals, editors and confirmation dialogs retain their keyboard ownership. If keys are intercepted by Windows/SSH, use `?` and `doctor terminal`; validate resize, focus, Ctrl+C, exit and terminal restoration on a **real controlling TTY**. Hosted PTY regression is not that proof. The UI neutralizes control characters, Unicode direction overrides and visually ignorable formatting (soft hyphen, zero-width space and word joiner) in untrusted conversation items, Git diff text, repository paths and provider labels. The selected-thread detail and offline footer apply the same display-only protection to thread IDs, model labels, Git branches/errors and App Server source. Change-request status applies the same protection to external Forge values. Typed local editors and Command Palette search also neutralize untrusted text; all original mutation payloads and external handoff targets are preserved. Mission Control footer input and retained diagnostic renderers use the same rendering protection, without altering queries or saved metadata. Only the display projection is modified; canonical Codex/Git data remains unchanged. The Terminal Drawer is a separate PTY emulator, not a sanitized preview.

## G2/G3 manual requirement, bug and cross-repository references
<!-- docs-section: workref -->

The opt-in `codex-tui workref` CLI records **local references only**. An original Feishu Project or TAPD item stays authoritative in its own platform. No enterprise API credentials are needed. Every imported URL, Target identity, contract and test result is **manually supplied and unverified**, not a live connection, a completion decision or a remote Codex resume permit.

For a match in Mission Control, `--target` must be the **exact credential-free** `app-server-target-identity` printed by `codex-tui doctor store` on the respective target/config, **not** its display name or hostname; use `codex-tui doctor codex --target NAME` when selecting another configured target. Pair it with the actual `codexHome` reported by `codex-tui status --json` on that Target and the exact native ThreadId. Both values are references, **not** remote-host authentication.

At startup the TUI reads the existing private SQLite workref envelope once. The **wide Mission Control selected-thread panel** shows the first two exact Target/CODEX_HOME/Thread matches with their manually recorded contracts, independently recorded evidence results and handoff counts. At **80-column** width, open the Thread to see the local linked-work hint. Invalid workref data is labeled **UNAVAILABLE**, not silently treated as zero links. The view never changes native Codex permissions, Attention or external issue status. CLI writes share TUI's exclusive lock; exit the TUI before editing workrefs, then restart to refresh the snapshot. There is no live cross-process refresh or automatic delivery.

To link the **currently selected live Codex session** without typing its Target/Home/Thread fields, use `.` → **Link current session to existing work item…**, or press `Ctrl+K` and search **Link current session to work item**. The editor lists up to five existing local keys; enter the exact key copied from the authoritative Feishu/TAPD item. The TUI captures the exact connected Target, observed CODEX_HOME and native ThreadId when opened, then rechecks the same view and identity at Enter. It derives a session alias from the repository name (adding `-2`, `-3`, etc. for collisions) and records role `development`. It never creates a ticket or sends a message. A successful SQLite commit refreshes the current TUI's in-memory workref view; CLI writes still require the TUI to exit because the existing exclusive writer is held. If the bounded worker queue rejects the write, the typed key remains in the editor for retry. Once the worker accepts it, the editor is frozen until the SQLite commit receipt arrives; a worker stop without a receipt is reported as **outcome unknown**, and the stale projection is hidden until SQLite is inspected. An accepted write is never described as cancelled or blindly retried.

~~~bash
# Copy the exact item ID, space and HTTPS URL from its real source.
codex-tui workref add --key BUG17 --provider tapd --space robot --type bug --id 17 --url "$ORIGINAL_TAPD_URL"
# For internal design work without an external ticket: --provider local-draft --type technical
codex-tui workref session --key BUG17 --alias soc --target "$SOC_TARGET_ID" --home "$SOC_CODEX_HOME" --thread "$SOC_THREAD_ID" --repo robot-app --role implementation
codex-tui workref session --key BUG17 --alias mcu --target "$MCU_TARGET_ID" --home "$MCU_CODEX_HOME" --thread "$MCU_THREAD_ID" --repo motor-fw --role firmware
codex-tui workref contract --key BUG17 --kind protocol --source robot-app/docs/protocol.md --revision r3 --git-sha "$FULL_40_CHAR_COMMIT"
codex-tui workref evidence --key BUG17 --kind integration --source "$JOINT_TEST_REPORT" --revision combo-3 --result unknown --environment bench
codex-tui workref handoff --key BUG17 --from soc --to mcu --summary "Review protocol revision r3"
codex-tui workref handoff-text --key BUG17 --index 0
# Reverse lookup uses the exact Target + CODEX_HOME + ThreadId tuple; no auto-resume.
codex-tui workref find --target "$SOC_TARGET_ID" --home "$SOC_CODEX_HOME" --thread "$SOC_THREAD_ID" --json
# Only after an actual acknowledgment from the destination:
codex-tui workref ack --key BUG17 --index 0 --receipt "$RECIPIENT_ACK_REFERENCE"
codex-tui workref show --key BUG17
codex-tui workref list --json
~~~

Choose contract kind from `protocol/api/abi/schema/config/data/model/other`. A Git-managed contract must be accompanied by its full 40-hex commit SHA (and a separate revision/gateway reference if appropriate). Evidence kind can be `commit/ci/unit/integration/device/acceptance/other`, with an explicit `passed/failed/partial/unknown` result and environment. **Unit PASS does not imply integration PASS, CI PASS does not imply physical-device or product acceptance, and a prepared handoff is not delivered.** The two session aliases distinguish identical ThreadIds on different Targets; all target/home values are references, not authentication.

Keep customer details, raw prompts, logs and credentials out of CLI history, command arguments and any exported JSON. CLI writes use the same private SQLite and exclusive writer lock as the TUI; an active interactive instance may block another writer rather than silently overwrite it. No central sync, Agent message bus or automatic platform status update exists. Real requirements, bugs and at least two cross-repository scenarios—including device/software/data combinations—are reserved for a **single later real-use qualification**. Automated tests establish only the local CLI/storage contract; v1.4 Stable status is unchanged.

## Evidence and state safety
<!-- docs-section: safety -->

SQLite persists personal metadata/planning overlays. Derived raw user/assistant message text is **not** indexed by default. To opt into searchable local transcript caching, set `[search] persist_local_transcripts = true` in config.toml; up to 10,000 items, at most 4,096 characters each for both message text and title, retained for at most 30 days from first local indexing when maintenance runs. Re-reading the same cached item does not renew its retention deadline. Turning the option off triggers logical removal of local transcript/FTS rows at the next startup, not forensic flash erasure. Codex remains the transcript authority. Never delete/overwrite a corrupt DB as a substitute for diagnosis; preserve store/WAL/SHM and create an offline recovery plan. Use `doctor bundle --output ./codex-tui-support` after checking privacy, and keep exact source SHA in bug reports. Do not publish Stable from the TUI.
