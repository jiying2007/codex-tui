# Approval delivery and maintained terminal restoration regressions

Defect correction against protected main `272857c90713d7aa21df622468472f2e58f043d8`.
The v1.4 feature boundary and stable release requirements do not change.

## Reproduced gaps

Eight production-reducer/parser cases on the unmodified source produce six
failures and two positive controls: repeated approval, competing cancellation,
repeated form cancellation and same-ID permission/command/file grant expansion.
The former generic response route wrote without the existing RPC deadline and
left a failed attempted write retryable. It emitted `InteractiveResolved` after
local write completion rather than preserving the distinction from server state.

## One checked response path

Approvals, permission decisions, explicit form cancellation and form answers now
share the existing bounded transient response ledger, tickets, admission helper,
transport deadline and NotSent/Written/Unknown receipt model. The old unchecked
command, handle method, actor route and writer are removed, not kept as shims.
No new RPC method, database schema, dependency or persisted answer copy is added.
The ledger stays bounded to 64 outstanding/uncertain requests. Refusal never
evicts uncertain work; tickets do not wrap and no response is retried automatically.

Each submission retains the original request plus the explicit resolution.
Approval variants retain opaque, debug-redacted original wire parameters so
same-ID changes in permissions, additional permissions, grantRoot, availability
hints or extensions cannot inherit an earlier decision. The actor revalidates
this identity and a live thread, then checks compatible payload construction
before I/O. Already queued request/resolution/thread-removal messages invalidate
the attempted response. This is local validation, not a server-side CAS.

The wire shapes remain the existing accept/decline/cancel decisions, turn-scoped
permission grants, form-answer payloads and explicit form-cancel error responses.
No auto-approval or new session-scoped grant is introduced. Approval presentation
remains the current command/reason and permission-summary UI; opaque context is
an identity fence, not a claim of a new complete permission-diff viewer.

NotSent is exclusively pre-I/O; explicit retry is possible. Written is local
transport completion, never service acknowledgement or proof of execution.
Unknown quarantines the connection and fences all competing decisions. Actor
loss is reported once after buffered receipts drain. Explicit editor close is
responsive but does not cancel admitted work; cancellation receipts clear only
the exact unchanged owned form, preserving later edits and unrelated editors.

## Maintained tests, not one-time certification

Tests cover all existing decision wire shapes, actual bounded full/closed queues,
missing backend, duplicates, old receipts, changed grants, broken writes and
stalls. A real loopback WebSocket fixture consumes Close before exercising the
production actor's response path; two observed requests and bounded event-channel
backpressure make ordering deterministic. It verifies Unknown, disconnected status,
actor exit and command-channel closure. This replaces the former source-string-only
actor-exit assertion. It is not a real Codex account/server process certification.

The already-merged #237 `tests/terminal_restoration.rs` runs the maintained Python 3 controlling-PTY
harness on Linux during ordinary `cargo test`. Both normal exit and a failed final
save (future schema injected only into disposable SQLite) drive help, palette,
Board navigation, resize and quit through the actual executable. Assertions cover
raw-mode observation, termios restoration, alternate screen, bracketed paste,
cursor, exit status and failure reporting after restoration. HOME/XDG/CODEX_HOME
are isolated, output is bounded and the harness has bounded waits. No live account
is contacted and no user's state is opened. The receipt explicitly disclaims
manual and real SSH qualification. Windows/macOS retain their native existing tests;
this new controlling-PTY regression is Linux-only.

## Evidence and boundaries

Exact before/after execution, source-tree identities and hosted/native results
belong to the PR evidence, not self-asserted pass values in this document. Existing
module ceilings and negative tests remain. New helper modules receive explicit
ceilings. Temporary patch/export infrastructure is excluded from the final tree.

Development completion is not stable readiness: stableReady=false and
publicationAllowed=false remain authoritative. Real terminal/account/internal
GitLab qualification and explicit stable publication authorization stay separate.
Memory-only request retention does not promise secure zeroization, restart-safe
retry, exactly-once delivery or crash/power-loss recovery. Synthetic soak and
TestBackend timing are not multihour live-account or end-to-end terminal SLO proofs.
