# User-input form identity and privacy

Frozen v1.4 defect follow-up from `b8e755f3e4a110b12b999c280fa12f43b7cf188c`.

## Reproduced failures

User-input editing previously kept only a request ID, question index and answer
map. Each render/commit looked up the latest pending request. A same-ID update
could replace the question, turn, item, owner or secret flag while retaining the
old answers. In particular, changing `isSecret` could display an already-entered
secret in plaintext. Duplicate delivery also moved the request to the back of
the pending list. Empty/duplicate question IDs could not round-trip through the
answer map without losing information.

## Correction

Replace those three independent editor fields with one private, ephemeral form
snapshot, question index and answers. Render the original question and privacy
flag; absent metadata defaults to masking, never plaintext. Before each answer
commit, require the complete original request to remain pending on the same live
thread. Refuse changed/removed/retargeted requests with a bilingual notice and
retain the unfinished answers. Explicit cancel then reopen starts a fresh form.
Identical retransmission preserves request order and editing progress.

User-input parsing and typed editor admission share validation for nonempty
thread/turn/item identity and a nonempty question list with unique nonblank IDs.
Do not tighten optional legacy fields, unknown extensions or free-text commas.
Resolution releases only its own form state, not another input mode's buffer.

## Verification and audit scope

`tests/user_input_intent.rs` contains 24 production reducer/renderer/parser cases.
On the exact original source tree it produces 19 failures and 5 positive controls;
the corrected source passes all 24. This includes an actual TestBackend plaintext
leak assertion, multipart answers, conflicting replacements, stale scope, duplicate
delivery, explicit close/reopen and missing-metadata masking. Direct replacement
of the input mode tests handler ownership; it is not a claim that the normal key
router opens a note while a form is active. Full suite and independent hosted
results are retained with the PR, not inferred from focused tests.

The audit also re-read StoreWorker/local-edit receipts, pending interactive routing,
launch execution, current CI paths and release boundaries. Existing local-save,
queue, palette, Review, read-fence and recovery protections remain. No additional
confirmed change to those areas is asserted by this patch. Original module ceilings
are unchanged; the form helper and validation helper have separate bounded ceilings.
No dependency, database schema, external RPC, extra per-poll task or shadow store.

## Limits

This guards the form observed by this process. It does not add server CAS, delivery
acknowledgement, remote exactly-once or durable answer drafts after exit/power loss.
Existing response admission/transport failure behavior is not reclassified as
success or safe retry. Secret masking is display protection, not secure-memory
zeroization. Synthetic timing/soak is not real terminal SLO, multihour account
stability or human/token ROI. Real-environment qualification and stable publication
remain separate; no manual pass, credential, protected ref or release setting changes.
