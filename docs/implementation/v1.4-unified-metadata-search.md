# v1.4 Unified Metadata Search

Status: implementation

The global `/` search remains a Registry metadata search. It never hydrates or
indexes transcript bodies; full-history transcript search remains the separate
`Ctrl+F` surface introduced in v1.3.

## Search inputs

Each Registry thread can match metadata already resident in the current
projection:

- thread id, title, workspace, cwd, source, model and project id;
- observed Codex Goal objective and status;
- Forge provider/host/project, Issues, change requests and pipelines;
- derived WorkCard title/workspace/branch/stage/tags/attention/overlay metadata;
- derived Goal, Worktree, ChangeRequest and related WorkCard links.

Generic tokens preserve the existing fuzzy-subsequence behavior and whitespace
means AND. Existing locality tokens (`local`, `stale`, `foreign-windows`,
`foreign-unix`, `relative`, `empty`) remain unchanged.

Scoped tokens are also supported:

- `thread:`, `cwd:`, `project:`
- `goal:`, `forge:`
- `card:` / `work:`
- `link:` / `related:`, `worktree:`
- `stage:`, `tag:`

Unknown scoped fields fail closed rather than silently becoming fuzzy text.

## Authority

Search consumes existing Codex/Git/Forge/WorkCard projections only. It creates
no new local authority and performs no RPC/file-system work while matching.
Transcript text, reasoning and tool-internal content are intentionally absent.

The matcher lives in `src/metadata_search.rs` so Registry projection logic does
not continue growing the mature `app.rs` search helper.
