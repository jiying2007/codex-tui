# Maintained automated terminal restoration regression

Baseline: `272857c90713d7aa21df622468472f2e58f043d8` (#236).

This change is independent of the unmerged approval-delivery candidate recorded
in #211 comment6007685388. It submits no approval, permission, cancellation or
transport source change and does not retry that blocked source write through a
different encoding, workflow or credential. That candidate remains unmerged and
requires reconciliation because this change owns the terminal-test paths.

The Linux integration test runs the real Cargo binary with --fake on a disposable
controlling PTY. It supplies terminal cursor-position replies, drives help/palette
input and resize, and tests normal exit plus final-save failure caused by schema999
only in a uniquely created temporary SQLite database. All profile roots are isolated.
It does not open a real Codex account, a real repository or a user's database.

Validation requires observed raw input, identical restored termios, the last mode
transition to be cleanup for alternate-screen/paste/cursor, the expected exit code,
and the injected failure after restoration. Checks use explicit exceptions and are
also exercised under Python -O. Negative fixtures remove/reorder cleanup, change
attributes or exit status, and supply unrelated errors; those are probe-validation
fixtures, not newly discovered production bugs. Failed runs retain transcripts and
failed-status receipts, never an old passing receipt. Output and waits are bounded;
parent-death signaling and isolated-session cleanup contain the child process.

The test is part of ordinary Linux cargo test, including the Ubuntu20.04 canonical
baseline. A read-only targeted workflow retains exact-checkout and binary-hash
receipts and raw transcripts. It does not modify existing required checks, workflow
permissions, release evidence or publication settings. Targeted runs intentionally
repeat this small test for retained artifacts; no CI-cost reduction is claimed.

No production Rust/Cargo/schema or module ceiling changes. No dependency. This is
Linux fake-backend testing, not full terminal-emulator coverage, Drawer certification,
real Windows SSH, human observation, external account qualification, a latency SLO
or stable-release authority. stableReady=false and publicationAllowed=false remain.

Exact candidate/main runs and their outcomes belong in the PR and #211 handoff.
