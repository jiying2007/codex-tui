# v1.4 audit closure

Audit baseline: `81a1725ca85b1028264f98427a57012077e794af`.
These are defect, performance and release-tooling changes under the v1.4 freeze,
not a new feature line. Development evidence never implies stable readiness.

## Implemented boundaries

- CLI preflight validates the entire route before state discovery or TTY/backend
  initialization. Help exits 0, malformed usage 2, blocked scoped Doctor 3.
  Integration tests run the actual binary with an empty PATH and isolated home.
- SQLite UI effects execute on one ordered worker with bounded queues. Explicit
  mutations are rejected visibly when full and acknowledged only after commit.
  Unsent operator snapshots coalesce; shutdown restores the TTY before an ordered,
  bounded final-state barrier. Contention tests verify order and rejection.
- Planning computation runs on a separate one-in-flight worker. New generations
  supersede obsolete results; only derived cards/indexes are installed. Drafts,
  selection/filter intent, mutations and transcript state stay on the UI thread.
  Snapshot copying and result installation still have measurable UI cost; this
  change does not claim a universal 50 ms end-to-end guarantee.
- Conversation presentation formats only the visible item window, including on
  changing revisions. Process-unique revision identities prevent stale reuse after
  the same thread is evicted/reloaded. Byte size of one item is not yet a new bound.
- SQLite recovery backup uses the bounded online backup API, not checkpoint/copy.
  Committed WAL contents survive pinned readers; publication refuses existing
  destinations. Restore still requires all other application instances stopped.
- Linux GNU artifacts declare glibc 2.31 as their ABI floor. Canonical Linux tests,
  packaging and archive smoke execute in Ubuntu 20.04 userspace; readelf checks
  strong imported symbols and binds LINUX-ABI.json to the source and binary hash.
  This ABI fixture is not an operating-system support/security recommendation.
- CI no longer reruns protocol replay after an all-targets suite already contains
  it. Superseded PR canonical runs cancel; independent main commits remain distinct.
  Canonical CI and development/release qualification remain separate authorities.
- Branch hygiene is dry-run first. Only an exact merged PR head already reachable
  from main can be deleted. Active/protected/release/archive/checkpoint refs and
  advanced or unreachable heads are retained. Apply requires the unchanged plan
  digest, exact repository, current main, and atomic per-ref leases.

## Measurement contract

Existing hot-render reports retain their schema. `release interaction-benchmark`
adds changed-state registry/Board/conversation paths plus actual planning capture,
worker compute and UI install phase distributions (20 warmups, 200 samples).
The TestBackend measurements exclude terminal I/O, networking and model inference;
human-time and model-token savings are deliberately null, not invented.

`soak --duration-seconds N` exercises the same resident process for at least N
seconds and the requested minimum cycles. It retains bounded RSS/CPU-tick samples,
actual duration and structural invariants. Weekly retained soak requests 300
seconds. Passing this synthetic workload is not an hours-long live-backend soak
or an exact-SHA controlling-TTY acceptance receipt.

## Remaining external evidence

Real Linux Codex/GitLab compatibility and Windows-SSH controlling-TTY restoration
remain exact-SHA requirements. Stable publication is still blocked without them.
Real-world time/token/cost savings require observational task data; no new metrics
service, accounting system or duplicate task authority is introduced.

Historical v1.1/v1.2/v1.3 plans remain historical checkpoints; v1.4 criteria govern
the active line. Necessary old-data/Git/protocol adapters are retained and tested.
Temporary audit-workbench files must not exist in the merged source tree.
