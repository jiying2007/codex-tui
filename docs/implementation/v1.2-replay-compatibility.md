# v1.2 protocol replay compatibility

The ReplayBackend is a deterministic compatibility backend, not a second Codex implementation.

Each JSONL fixture is decoded by the same App Server wire decoder used in production. Registry notifications are then applied through the same production normalization path before ReplayBackend exposes snapshots through the existing CodexBackend contract.

Retained classes:

- **current** — current supported registry shapes;
- **previous-stable** — older/omitted optional fields remain compatible;
- **unknown-events** — unknown future notifications fail soft and do not invent state;
- **malformed** — invalid wire input fails closed with bounded error context.

The scheduled `protocol-compatibility` workflow runs without Codex credentials or paid model inference. It complements, rather than replaces, real App Server qualification.
