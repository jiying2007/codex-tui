## Retained boundaries

Restore still requires an **offline destination**: stop all processes holding that
live database before invoking recovery. Snapshotting a concurrently written source
is different from safely replacing an actively opened destination. Multi-file
rename rollback is best-effort error recovery, not power-loss atomicity or a
cross-process locking protocol. Retained recovery directories are never silently
removed when they may hold the only surviving component.

The shutdown guarantee covers recoverable event-loop errors. Panic, process kill,
host crash and disk failure are not converted into successful durability claims.

The sustained soak is one process exercising synthetic reducer churn with bounded
resource samples. It is not real-account/network/terminal traffic, multi-hour leak
certification or a substitute for external environment qualification. The shared
validator verifies artifact identity and internal coverage, not truthfulness of
arbitrary externally supplied data. The automated qualification builder is used
only after successful tests in the trusted exact-source workflow.

Real Linux account/provider and internal GitLab qualification, controlling-TTY
restoration and human-visible Windows SSH behavior remain manual/external gates.
`stableReady=false` and `publicationAllowed=false` remain unchanged. No existing
release, tag, branch protection or immutable-release policy is weakened.

Temporary source/materialization tooling is removed before merge. Cleanup decisions
continue to require explicit proof; absence of an open PR alone never authorizes
deleting a historical branch.

Post-merge hygiene is scoped to the just-merged same-repository PR branch. It runs
trusted default-branch code, requires the event's exact head, preserves protected
and release refs, proves merged ancestry or a complete squash tree delta, then
uses the existing fresh-plan checksum and exact-head atomic lease. An advanced
branch is refused; an already deleted branch is a verified no-op. A closed but
unmerged PR is never a deletion authority. The retained plan/receipt makes each
automated cleanup auditable without enabling repository-wide force deletion.
