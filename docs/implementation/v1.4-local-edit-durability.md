# Local editor write receipts

Frozen v1.4 defect follow-up from f7ad98c092214977f2c2512a448940a4f3445ec1.

Scratch creation, thread/source notes, scratch notes and Saved Views used to clear
the editor before admission to the bounded SQLite queue. Failed admission or
write/refresh could therefore lose the only draft. Invalid visible-field input
also cleared before validation.

The original operation still owns its existing typed Effect. One ephemeral
in-flight editor slot adds a process-unique ticket and editor revision. Only the
matching ordered worker receipt can retire unchanged input. The check also
compares original raw input and current editor payload/target identity; the
ephemeral revision only advances while a local save is pending. Later input,
including edit/undo and cancel/reopen, is retained. Duplicate submission is refused while
pending, but editing/navigation/explicit close remain responsive. Closing does
not undo an accepted write, and a later failure does not resurrect discarded input.

Queue refusal retains the draft without declaring a healthy database read-only.
Accepted failures and stopped workers report an unconfirmed outcome, never a
rollback or a safe automatic retry. A write may have committed before projection
refresh failed. Existing backend read-only and exit-barrier error handling remain.
Unrelated planning receipts cannot close an editor. Invalid Saved View fields stay
in the text editor for correction. No schema, Cargo, RPC or persistent shadow copy
was added. Existing module limits and real qualification/publication gates remain.

Validation uses production reducers, actual bounded StoreWorker admission and
SQLite writes, old/matching receipts, full-queue recovery, write failure, injected
worker termination and the final-save barrier. Eleven original reducer tests
reproduce eight failures and three positive controls; corrected validation covers 632 Rust and 34 Python tests, including
the actual effect dispatcher for all four editor types with real SQLite success
and failure. These candidate results are not final-main release evidence.
Before/after logs, the exact tested tree and independent hosted verification
belong in the PR receipt. The original unexecuted candidate had a missing import;
that compile failure is retained before the corrected full-suite pass.
The first independent hosted candidate also rejected the deprecated atomic
fetch_update alias on Rust 1.99. Ticket allocation now uses the MSRV-compatible
compare-exchange loop, with exhaustion and concurrent-uniqueness tests. No
warning suppression or toolchain requirement increase was used.

Verification code runs without repository-write authority. Exporting tested
source blobs, when needed by the connector, uses a separate data-only job which
never executes repository code or changes any ref. Temporary files are excluded
from the final tree and squash merge.

Scope limits: at most one pending local editor write; drafts remain memory-only
while editing. Explicit exit/SIGKILL/power loss is not draft durability certification.
This is not multi-process CAS or a cross-table atomic write-plus-projection read.
Synthetic diagnostics do not establish human/token ROI or real terminal SLO.
