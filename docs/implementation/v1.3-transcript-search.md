# v1.3 Transcript Search

Status: implementation work package under the v1.3 Search & Multi-Target plan

## Operator flow

`Ctrl+F` opens a dedicated transcript-history query editor from any normal view.

After Enter:

1. codex-tui immediately searches the derived local SQLite transcript index;
2. when the connected App Server supports the experimental search API, `thread/search`
   searches persisted Codex history and replaces the local result set as authority;
3. `thread/searchOccurrences` upgrades thread matches to exact turn/item locations;
4. Enter on a result loads the matching turn and highlights the matching visible item.

The result surface is bounded to 96 hits and remains keyboard-only friendly:
`j/k`, arrows, Enter, Ctrl+F and Esc.

## Authority and privacy

Codex App Server remains conversation/history authority.

SQLite derived transcript persistence is explicitly opt-in via `[search] persist_local_transcripts = true`; the first-deployment default is off. On opt-in, index retention is capped at 10,000 documents, 4,096 characters each for message text and title and 30 days from the **first local observation** (not last hydration), with maintenance on startup and indexing. Re-reading the same indexed item must not reset its retention clock. Disabling triggers logical deletion of derived SQLite/FTS rows at startup, not forensic secure erase.

SQLite is only an acceleration/fallback layer for pages that codex-tui has already
observed. It stores user messages and final assistant messages for search. Reasoning
items, tool internals and other non-user-visible conversation items are intentionally
excluded from the derived transcript index.

The local result receipt always reports `complete=false`, because it cannot claim
full-history authority. A modern App Server result is tagged `app-server` and may
report completeness after cursor exhaustion.

## Compatibility

The App Server initialize handshake enables the experimental API so current Codex
servers may expose `thread/search` and `thread/searchOccurrences`.

Older/unsupported servers fail soft:

- Registry/conversation operation remains available;
- locally indexed transcript pages remain searchable;
- the search overlay explains that full-history App Server search is unavailable.

## Persistence

SQLite schema v4 adds `transcript_documents` plus an optional FTS5 acceleration
table. The canonical Codex transcript is never migrated into SQLite.

If FTS5 is unavailable, the operator-state database remains usable and transcript
search falls back to a bounded case-insensitive LIKE query over derived documents.
