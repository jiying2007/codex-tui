# v1.4 Review Evidence and External Open

Status: implementation

## Review evidence

Review remains a projection over Git + Forge authorities. The left/top evidence
panel now makes the following state explicit without inventing a local review
authority:

- tracked/untracked Git change count and diff truncation;
- Forge provider / host / repository identity and freshness;
- current-branch change request state, draft state and merge status;
- current-branch pipeline status;
- provider review evidence: approval requirement/remaining count,
  changes-requested count and unresolved discussions when supported.

Unavailable provider capabilities render as unavailable/n/a rather than being
inferred.

## External editor and browser

Review keeps two distinct bounded actions:

- `e`: open the selected changed file in the external editor;
- `o`: open the current branch's Forge change request in the system browser,
  falling back to the repository web URL when no current-branch change request
  is projected.

External process spawning lives in `runtime_external.rs`, outside the reducer
and renderer.

The Review `e` path is scoped to the current, matching Git worktree identity.
Porcelain-v2 paths are interpreted relative to the **worktree root**, not a
possibly nested Codex thread cwd. Before spawning any editor, absolute or
parent-component paths, missing targets and symlink resolutions escaping that
root are rejected. If Git identity is absent/stale, the Review reports an
explicit error instead of guessing a target.

Editor selection:

- `CODEX_TUI_EDITOR` when set;
- otherwise `code`.

Browser selection:

- `CODEX_TUI_BROWSER` when set;
- Windows: `rundll32.exe url.dll,FileProtocolHandler`;
- macOS: `open`;
- other supported desktop Unix: `xdg-open`.

Browser targets must be valid HTTP(S) URLs with a host. Explicit userinfo,
malformed ports, whitespace, control/bidi format characters and backslashes
are rejected before any process starts, preventing ambiguous URL parsing
and credential-bearing links. Valid Forge-owned URLs are passed through
without rewriting or persisting them.

## Authority and failure behavior

- Git remains authoritative for changed-file/diff content.
- Forge remains authoritative for change request, pipeline, approval and
  discussion evidence.
- external-open failure becomes an operator notice; it does not mutate Git,
  Forge, WorkCard or conversation state.
- opening external tools is never executed from headless mode.
