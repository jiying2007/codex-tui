# v1.4 Long-thread Viewport Cache

Status: implementation

## Goal

Long loaded conversations must not reformat and allocate presentation text for
every item on every terminal frame.

The Codex App Server remains the canonical conversation authority. This change
only bounds the local presentation path.

## Revision-bound presentation cache

`ConversationState` owns a monotonic presentation revision. Replacing the
loaded page or prepending older history increments that revision.

The Thread renderer keeps one bounded-process presentation cache keyed by:

- thread id;
- conversation presentation revision.

A cache hit reuses preformatted item text. A revision change rebuilds the
presentation from the current authoritative in-memory conversation.

Search-result highlighting is intentionally not cached. It is applied only to
the visible item slice, so changing the active Ctrl+F hit cannot leave stale
highlight state behind.

## Visible item window

Thread `scroll` is treated as an item offset. Rendering selects a window that
starts at the current offset and is bounded to:

- at least 64 items when available;
- at most 512 items;
- normally about four times the visible terminal row count.

Only that slice becomes Ratatui `Line` values for the frame. A scrollbar and
`items START-END/TOTAL` title expose the current position.

Pending interactive approval/input still forces the conversation offset to zero
so the NEEDS YOU prompt remains visible.

## Paging and authority

Scrolling above offset zero retains the existing behavior: when App Server
reports older cursors, codex-tui requests the older page and prepends it.
Prepending bumps the presentation revision, invalidating the cache.

The cache never changes:

- App Server pagination;
- transcript-search authority;
- resident conversation LRU limits;
- saved scroll/follow state;
- prompt/approval semantics.

## Qualification

Retained tests cover:

- 10k item window remains <=512 items;
- oversized offsets clamp to the final item;
- page replacement/prepend increments presentation revision;
- presentation cache rebuilds when the revision changes;
- existing Ctrl+F search-hit highlighting remains applied after slicing.
