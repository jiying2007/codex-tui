# v1.4 asynchronous read-boundary audit

Baseline: #226 main `88104fa6fd2b205a896badcca4269e88ab0deaa3`.

## Reviewed invariants

Git and Forge remain the authorities for observed state; a delayed read must not
restore an earlier accepted request's result after newer operator intent. The
bounded actors still execute independent requests concurrently. Fencing applies
only to reads, never to mutation plans, execution or receipts.

The ephemeral read ticket follows the command through worker execution and the
bounded event queue. Consumption checks the ticket again, including a result that
was buffered before a newer command was accepted. Failed full/closed/busy admission
does not invalidate an earlier accepted read. The weak scope index is pruned on
successful admission and retains no response payload or persistent generation.
Drain work has an explicit budget. Snapshot keys use cwd (including leader changes);
Review keys use thread identity (including cwd A-B-A navigation). Git and Forge keep
separate fences and their existing queue/concurrency limits.

Forge review results retain the exact requested provider, host, repository identity,
path, cwd, thread and IID. Installation compares that target to the live thread and
current observation, and validates the returned summary's thread/cwd/IID. A cached
review cannot cross an observation's repository identity change merely because
its IID matches. Unknown/removed-thread and former-cwd observations cannot be
reintroduced by the fallback installation path. Project-wide observation fanout
and branch-specific selection remain unchanged.

## Verification

Tests drive the production actor with controlled completion gates and the actual
Git handle with synthetic queue events. Original-code regressions exercise both
late and already-buffered results, five Forge identity/liveness failures and two
positive installs. The old review call drops its target because the original API
cannot carry it; after the result API changes only this call adapter changes, not
the assertions. Additional fence tests cover queue rejection, independent scopes,
retired-key pruning and bounded draining. A deliberate mutation that admits every
ticket must fail before the verified source is restored. Full native regression
and unchanged existing module ceilings must pass; new modules receive small
explicit ceilings. Temporary audit transport is removed before final verification.

## Boundaries

This is latest-accepted-read fencing within one handle's scope, not an atomic Git
filesystem snapshot, remote exactly-once semantics, cancellation of side effects,
or globally ordered observations across independent worktree scopes. Old read work
may finish but its stale payload is discarded. No persistent schema, Cargo dependency,
public mutation API, authorization rule or publication gate is added or relaxed.

Local execution is unavailable for this audit; GitHub-hosted execution and reported
artifact digests are distinguished from independent local verification. Synthetic
soak/performance does not certify real accounts, internal GitLab or controlling-TTY
behavior. `stableReady=false` and `publicationAllowed=false` remain unchanged.
