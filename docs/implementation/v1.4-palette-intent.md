# v1.4 command palette execution intent

Baseline: `89385fe39db4fc93826778e0c6ae2780c877c59f` (#232).

The palette already froze and ranked its command list, but Enter closed the
palette and dispatched the stored command against live context without checking
its original target. Context-menu and editor protection did not cover this earlier
boundary. Row selection, thread removal, cwd/workspace changes or command
availability changes could redirect a pin, prompt, Review, queue, Scratch or
context action before those later editors opened.

One ephemeral scope is captured at palette open. Enter validates the selected
command against current availability and the original view, SourceRef, cwd and
Saved View identity. Workspace matters for Scratch/context commands; repository
identity matters for Review/workspace/worktree/terminal/context commands. A scoped
target must remain live. Changed context closes the palette with a bilingual
refusal and does not dispatch. Empty fuzzy results stay open; closed palettes
cannot dispatch. Cancellation and successful consumption clear the scope.

Help, search, transcript search, Board navigation and closing the existing global
Terminal Drawer remain global commands; they do not need a still-live selected
item, but must remain available. Ordinary display metadata updates and a reorder
that preserves the same selected identity do not block execution. Direct keyboard
commands outside the palette continue to use live context as before.

Tests exercise the actual runtime palette Enter handler with production reducer
refreshes, not only the scope comparison helper. Controlled baseline failures and
positive controls precede the full corrected native suite. The existing empty
result, fuzzy ranking, bilingual matching and pasted-query tests remain.

The scope contains only small identities, no transcript/payload snapshots; it is
captured once on open and rechecked once on Enter, with no new external calls,
persistent state, Cargo dependency or publication permission. Existing module
ceilings are unchanged. The helper and focused tests have explicit ceilings.
Temporary candidate workflow/files must be absent from final source before merge.

These are local UI intent checks, not remote compare-and-swap, atomic filesystem
observation or exactly-once execution. Accepted direct actions, subsequent editor
confirmation and backend revalidation retain their existing contracts. No real
account/internal GitLab/controlling-TTY PASS, terminal SLO, multihour leak-free
certification or human/token savings percentage is implied. Stable readiness and
publication remain governed by their existing exact-source external evidence.
