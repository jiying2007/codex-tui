# v1.2 mature presentation modes

Status: P2 implementation

This slice completes the v1.2 accessibility-mature-mode objective without adding a second renderer or a new product authority.

## Configuration

The local `[ui]` configuration accepts:

```toml
presentation = "normal" # normal | quiet | screen-reader
```

Missing values default to `normal`, so existing installations retain their current behavior without a config migration.

## Redraw policy

The renderer remains state-driven: codex-tui only draws when `needs_render` is set.

Presentation mode adds one additional policy for **background-only** redraws:

| Mode | Minimum background redraw interval | Direct input |
| --- | ---: | --- |
| `normal` | 0 ms | immediate |
| `quiet` | 100 ms | immediate |
| `screen-reader` | 500 ms | immediate |

Keyboard press/repeat events, bracketed-paste events and terminal resize events set an urgent-render flag and bypass the background interval. Background Registry/Git/Forge/PTY/notification updates remain authoritative and are not dropped; multiple updates can be presented by one coalesced frame.

## Accessibility boundary

`screen-reader` is intentionally a screen-reader-oriented presentation policy, not a screen-reader protocol implementation. It builds on the existing M7d1 accessibility contract:

- keyboard-only reachability;
- textual selection/focus/attention semantics rather than color-only state;
- grapheme-safe CJK/emoji rendering;
- no private-use icon-font dependency.

The mode reduces repeated terminal repaint churn while keeping operator interactions responsive.

## Non-goals

This slice does not add:

- a second renderer;
- an assistive-technology protocol;
- a new terminal backend;
- a theme engine;
- persistent workflow/task state;
- Codex/Git/Forge authority;
- a daemon or remote service.

The implementation is isolated in `src/presentation.rs`, and `src/main.rs` remains under the existing 1900-line v1.2 ratchet.
