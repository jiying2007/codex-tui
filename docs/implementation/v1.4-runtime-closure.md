# v1.4 runtime consistency and archive audit

Reviewed baseline: `d1d133c782a87ac1cf0044a77d51238737e2560b`.
This follow-up remains within the frozen defect/compatibility/qualification scope.
`stableReady=false` and `publicationAllowed=false` remain unchanged.

## Reproduced runtime defects

The original initial-connection path reapplied the boot-time local snapshot after
installing the server snapshot. Operator filter changes while connection was pending
were lost. Initial install now performs only the two authoritative backend actions;
local state is still applied once, before interaction starts. A process-runtime unit
test reproduces the old filter rollback and preserves current intent after the fix.

`PlanningSnapshotLoaded` reset the Board cursor and retained only a numeric Saved
View index. Asynchronous planning installation also retained a positional cursor
when sorting changed. A shared identity-based selection capture/restore preserves
the current Saved View ID and selected WorkCard `(local_id, anchor)`. Worker output
captures selection at installation, not at submission, so navigation during the
computation is not undone. Removed views fall back to the built-in view; removed
cards clamp safely. Visible-card lookup is restricted to the Board surface.

A completed planning generation previously never expired without external events.
The worker now records the earliest snooze/provenance transition after computation.
The UI checks that scalar deadline, not all cards, at idle polls. Shared freshness
limits drive both projection and invalidation. Wall-clock rollback invalidates the
projection; output already expired in transit is rejected and recomputed. This does
not change the source authority, guarantee progress during arbitrary continuous
clock changes, or turn synthetic tests into real-terminal latency evidence.

Six regression cases failed against the respective original logic and pass after
the fixes. Additional cases cover idle no-recompute, removed selection, wall-clock
rollback and time-expired in-flight results. Existing data-generation fences remain.

## Measured reconciliation and obsolete-model removal

Soak now reads the actual reconciler/accepted-install counter rather than incrementing
an expected orchestrator count or hard-coding zero UI-only reconciliations. A temporary
mutation made the real help-toggle path reconcile planning: two existing soak tests
failed. Removing the mutation restored all soak tests. No mutation remains in source.

The test-only duplicate write-behind state machine and its compatibility methods
were removed from the backend. The production StoreWorker now has a direct deadline
regression: continuing edits must not postpone an already-due write. Existing queue,
commit-order and final-flush tests remain. No required data/protocol migration was
removed and no existing module ceiling was increased.

## Native archive identity and layout

All platform metadata now contains the actual executable SHA-256. Packaging and
native extraction smoke validate the metadata schema, native platform/triple family,
executable basename, version/tag/source and bytes. A backend-free existing diagnostic
reads the embedded source SHA after extraction; one sample is only an identity probe.
Six verifier negatives (schema, platform, triple, name, hash and compiled source) were
accepted by the previous verifier and are rejected now.

Archive member preflight rejects aliases, duplicate/case-colliding paths, loose or
multiple roots, file/directory collisions and special/link entries before extraction.
Member count and declared uncompressed bytes are bounded at 4,096 and 256 MiB. Ten
malformed ZIP/TAR subcases passed extraction before and fail before extraction now.
Positive native ZIP/TAR layouts remain supported, including Python 3.8 helpers.

These checks prove consistency of trusted workflow artifacts, not authenticity of
untrusted executable self-reports. They do not replace artifact provenance, native
smoke, stable-evidence qualification or publication authorization.

## Verification and boundaries

Local all-target/all-feature regression: 468 Rust tests and 31 Python tests pass;
Clippy with denied warnings, formatter, both prior module ratchets, active plan and
completion checks pass. Archive regressions also pass under Python optimization.
PR and fresh-main native checks, performance, sustained soak and preview packaging
are retained separately with their actual source SHA and workflow run identifiers.

The performance workflow also covers all `src/app/**` helpers, preventing future
clock/selection changes from silently skipping diagnostic coverage. Temporary source
transport files/workflows are removed before squash merge. No new product features,
credentials, manual PASS, stable tag/release or protection bypass are introduced.

Real accounts/internal GitLab, Windows-SSH controlling-TTY restoration and final
stable-publication authorization remain external. Offline restore and power-loss
limits from the previous audit remain explicit. Five-minute synthetic soak does
not establish multi-hour leak freedom or measured human-time/model-token savings.
