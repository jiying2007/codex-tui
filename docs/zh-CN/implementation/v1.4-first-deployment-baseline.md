# v1.4 首次部署基线：不承担未部署版本升级兼容
<!-- docs-section: overview -->

**语言 / Language:** [English](../../implementation/v1.4-first-deployment-baseline.md) · [简体中文](v1.4-first-deployment-baseline.md)

决策时间：2026-10-08。虽然 GitHub 已发布 v1.0.0，但维护者确认 **v1.0 与 v1.4 均未实际应用部署**。因此 v1.4 正式投入使用时按首次安装，而不是升级已运行的产品。仅撤销**无部署事实的旧产品向后兼容**，不撤销当前外部软件、数据库安全或运行可靠性要求。

## 移除的历史兼容链
<!-- docs-section: retired -->

- 不读取或自动导入 `state-v1.json`，也没有自动改名或保存旧 JSON 备份的链路。
- 不接受 SQLite v1、v2、v3 旧数据库或旧恢复镜像做静默升级。
- 首次安装直接初始化当前 SQLite v4；若发现未知未来版本、旧镜像或损坏数据，则失败并保留原文件，不清空重建。
- 不以 v1.0–v1.3 的假定部署为理由增加发布阻塞、回归数据夹具或持久迁移 Shim。
- 已公开 GitHub Tag/Release、历史开发计划、提交、审查和保留证据仍是审计事实，不随代码清理一起删除。

## 防回退检查
<!-- docs-section: regression -->

`scripts/architecture/check_first_deployment.py` 在 CI、Development Qualification、Release Gate 运行；负例会检测旧 JSON/SQLite 迁移是否悄悄恢复、历史 LOC 限额是否重新作为当前资格、数据恢复是否被削弱。

当前开发资格只接受 v1.4 完成状态，已退役 v1.2/v1.3 的独立可执行验证器；历史 JSON 资料仍保留以便审计。模拟测试只验证契约，不等于真实已部署系统发生过升级。

## 仍必须满足的互操作与安全
<!-- docs-section: safety -->

配置 TOML、当前 SQLite Envelope、备份/WAL、一致性恢复、未来版本拒绝、Codex App Server 能力探测、GitLab/GitHub 互操作、Linux ABI、真实控制 TTY、主线保护和不可变发布仍全部保留。管理员及真实环境证据独立验收；使用新程序前应真正验证 Codex、目标内部 GitLab 和终端控制路径。

未来**实际部署** v1.4 之后，任何可能破坏数据库或行为的版本迭代都必须另行定义数据迁移、备份与回滚政策，不能把本次“未部署版本”决策推广为永远不兼容旧用户。
