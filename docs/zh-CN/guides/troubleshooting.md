# 故障排查：Codex、Forge、SSH 与 SQLite
<!-- docs-section: overview -->

**Language / 语言:** [English](../../guides/troubleshooting.md) · [简体中文](troubleshooting.md)

先确认失败的是哪个权威，不要靠删除本地状态、改写上游凭据或伪造恢复成功。记录精确源码 SHA、目标类型和脱敏错误类别。敏感漏洞按 [安全披露](../../../SECURITY.zh-CN.md) 处理。

**会话监听生命周期：** 取消元数据搜索或从看板返回时，必须保留仍可返回会话的监听。后端快照、历史完成和提示提交失败产生的 reducer 动作，与键盘动作一样必须实际分发；否则界面已经忘记监听，后端却仍在反复读取历史。提示提交确认后，所有权保留到权威历史或失败返回。Linux 实际程序回归通过有序通知屏障同时检查漏刷新和空闲／已删除会话的多余 RPC，并记录绑定源码与程序哈希的双会话内存、文件描述符观测。这些隔离夹具不等同于真实 Codex、SSH 验收或全局内存上限。

## App Server 连接失败或线程缺失
<!-- docs-section: codex -->

**活跃历史与正文缓存分离：** 即使正文被淘汰或 Registry 元数据暂为空闲，进行中的历史仍保留仅含 ID 的订阅所有权。仅完整的当前历史观测更新活跃状态，旧分页和精确搜索命中不能建立或清除它。权威完成或读取失败会释放该所有权，退出及删除随监听一起清理。集合受已订阅 ID 限制，不额外保留正文页面。

**缓存淘汰后的返回：** 搜索与 Board 返回路径可能比 16 项历史展示缓存保留得更久。返回有效 Thread 时，仅在缓存缺失时补发一次有界读取；已有加载中或错误条目不会自动重试。暂停跟随的历史搜索保留原 turn/item 命中，不静默跳到最新正文。已删除的临时目标与仓库工具视图不会因此新增读取。控制终端回归核实 32 个后台历史完成、命中/淘汰/删除/失败对照、最终退订及限定测试负载的 RSS/描述符采样，不替代真实账号验收或产品全局内存上限。

**从仅存在于历史搜索的会话取消搜索：** 历史命中的会话可以尚未进入 Registry；只要临时监听仍有效，取消本地搜索会返回该 Thread，且不重复加载历史。已删除／归档或加载失败的临时目标不会被恢复；这一例外也不赋予未注册会话仓库工具权限。受控回归同时检查返回界面与后续历史请求。

**显式历史移除：** 历史搜索目标可能尚未进入 Registry，但已经可以读取。因此，归档／删除通知直接移除 actor 侧的历史与会话队列监听，不依赖注册表行发生变化；原有失败事件同时清理界面的临时所有权。正文缓存不作为订阅授权，不影响其他已监听目标，也不新增持久墓碑。保留的移除场景刻意让模拟历史接口在通知后仍可读取，避免服务端“目标不存在”错误掩盖漏退订。命令背压退订已有独立回归，完整真实负载资格仍需独立验收。

**高负载下释放订阅：** 历史和 Thread Queue 停止监听不再依赖 actor 命令队列有空位。只有命令成功准入才登记期望监听；排队的旧读取不能恢复已释放的监听，actor 退出时清空两组记录。已经开始的一次读取可以完成，已接受写命令仍保留原有执行与不重放约束；重新打开页面会显式准入新监听。实际程序背压回归填满生产队列，检查关闭、保留、重开和断连，不替代全局内存或真实账号验收。

**历史订阅所有权：** reducer 在视图切换、搜索跳转、Prompt 回执及会话清单更新后统一核对后端历史监听。只保留当前／可返回会话以及正在工作或发送未完成的已监听会话；被替代且非活跃的目标会显式发送 StopWatchingConversation。正文缓存仍存在不代表后端仍在监听。此举减少无用的 RPC 历史重读，但不等同于已获得全局 RSS 实测上限。

执行 `codex-tui doctor codex`（命名目标可附 `--target NAME`），独立检查真实 `codex --version` 和账号登录。远程 WebSocket/Unix 建连及握手受超时限制，超时不代表已发出的请求必定未执行。核对服务进程、TLS 代理、认证及能力错误；可选方法可以降级，但不会自动切换 `--fake`。Issue 不得粘贴 Bearer Token。

stdio 半帧缓冲会跨定时器或命令取消保留；后端 EOF 的最后离线快照只交付一次。重复或循环游标、分页无进展以及总预算耗尽都会明确标为清单不完整，不能作为完整的变更授权证据。搜索跳转在有界全局历史中定位精确条目，并保留相同查询范围的续页游标；目标删除或预算耗尽时报告失败，不静默跳到其他位置。

RPC 通知最多保留 1024 条且受 16 MiB 载荷记账预算限制。待处理交互请求最多 64 条、每条 256 KiB、累计 4 MiB。分页限制为 1024 页、200,000 个身份、32 MiB 身份存储记账预算及整次扫描 120 秒。这些是载荷或记账限制，不是实测 RSS 保证。过载会明确终止或隔离会话，不随机丢弃审批消息，也不重放写 RPC；正常 5 万条清单仍可在这些预算内处理。

发送被取消或失败后，连接进入隔离状态：部分交付结果未知，后续请求不能接到未完成帧上，也不会自动重放写操作。包括通知在内的每次发送都受五秒截止时间限制。RPC 期间的底层读取、JSON 解码失败或 EOF 不能再被报告为连接正常。合法的可选方法拒绝，以及仅等待响应时被取消，不会隔离本来完整的连接。

连接状态覆盖整个 RPC 会话，而不只是底层通信：消息条数或字节准入失败与传输失败，都会使会话不可用并标为离线。Registry 启动加载已隔离时，不再发起可选 loaded-list 探测，也不覆盖首个故障原因。合法的可选方法拒绝仍表示连接正常但能力降级。

每个 stdio 连接用最多包含一个任务的任务集合持有 stderr 读取器。初始化失败、隔离搜索完成或调用取消后，连接释放会取消读取；后代继续持有写端也不能维持无主读取器。取消在 Tokio 下一次调度任务时完成，不是析构函数同步等待完成。不会因此终止无关后代，也不保留其 stderr 正文。

## GitLab/GitHub 不可用或字段不全
<!-- docs-section: forge -->

**审批/合并的修订版本确认：** 待确认的 Forge 操作计划记录当前 GitHub PR／GitLab MR 观测到的完整 HEAD SHA。若 SHA 缺失、格式错误，或从预览到执行期间发生变化，操作拒绝执行；请刷新 Forge 数据并重新审核确认。已有审批与结果不确定后的恢复核验不得拿其他修订版本冒充成功。保留 GitHub/GitLab 原有携带 SHA 的写请求保护；这不意味着能原子阻止上游管理员并发改动。


进入出现问题的仓库，**私下**检查 `git remote -v`，依次执行 `codex-tui doctor git`、`codex-tui doctor forge`。在工具外登录对应主机的 `glab/gh`。GitLab Issue/MR/Pipeline 独立探测，一项能力失败不应让其他成功内容消失。`doctor compat` Ready 不等于内部 GitLab PASS；内部部署参考 [能力准入](../qualification/provider.md)。

GitLab 审批状态 JSON 异常，或缺少 `rules`、`approvals_required`、`approved` 时，证据属于未知，客户端阻断合并。明确有效的空规则数组不同于字段缺失；客户端检查不替代 GitLab 服务端保护。

Forge 的 stdout/stderr 读取与命令共享同一个异步作用域及原有五秒期限。超时或调用者取消时，两个本地管道读取端同时释放，即使后代进程仍持有写端，也不会遗留脱离作用域的读取任务。这不授予终止无关进程组或重试未知结果写操作的权限。

## Windows 路径拼接或仓库会话不匹配
<!-- docs-section: cwd -->

**Forge 确认与回读：** 审批/合并确认框单独显示完整的已审阅 HEAD，不再依赖有数量上限的前置条件列表；确认和取消按键置于可变长度详情之前。GitHub 审批证据必须是当前认证用户的最新审阅，状态为 `APPROVED`，且 `commit_id` 与已确认提交完全一致；旧提交或缺失版本的审批不足以证明成功。正常写入成功回读与不确定结果恢复均重新核对已确认 HEAD；审批读取前后都检查 HEAD，包括“已满足”的短路路径。GitLab 的 `approved_by` 本身不绑定版本，因此在审批回读前后观察 MR HEAD。版本变化保留为结果未知，启动恢复不重放写入。这些独立 API 读取不是原子租约，也不能证明不存在 ABA 变化；隔离 PTY/模拟服务测试不等于真实账号或内部 GitLab 验收。


**Worktree 变更身份：** 在准入前、异步前置条件探测结束并即将执行 Git 写入前、以及结果核验和恢复阶段，都再次核对计划中的 Git common-dir。准入后工作目录符号链接若已改指，则拒绝执行。此举属于纵深防护，**不是**抵御同一用户恶意并发目录替换的原子文件系统身份租约，不能据此宣称绝对无竞争窗口。

Windows→SSH Ubuntu 使用的是 **Ubuntu 侧** Codex Home、当前工作目录及 Git 身份。历史会话包含 Windows cwd 时属于外来源，不是本地 Ubuntu Checkout。核对 `doctor codex` 的路径和实际仓库目录的 `doctor git`；不要拼接 Windows 绝对路径，也不要编造不存在的 Ubuntu 本地会话。

Git 路径身份保留尾随空格、制表符和内嵌换行，只移除一条响应末尾的协议结束符。非 UTF-8、无法解析为真实路径或与被探测 cwd 不匹配的路径及状态身份会被拒绝，不再改写成其他路径。编辑器在解析选中文件前再次核对真实 cwd 与观测工作树根目录的关系；这不代表能原子阻止同一用户并发替换文件系统对象。

每次 Git 命令的身份 stdout 限制为 64 KiB，status stdout 限制为 2 MiB，stderr 限制为 64 KiB，并保持原有三秒期限。状态解析最多允许 8192 条非空记录，包括头记录及重命名原路径记录。超限或不完整的元数据/status 返回错误，不能被视为干净仓库或完整 Review。diff 展示保留已有的有界前缀及显式截断标记。这些是单操作预算，不是经过认证的进程 RSS 上限。

相同 cwd 的会话投影及规划快照共享不可变文件变更清单，不再按会话逐项深复制。明确加载的 Review 持有自己的展示副本；独立探测和不同工作树没有加入全局缓存。2 MiB/8192 的预算会主动降级超大脏清单，仍需在代表性工作负载上验证。

## Drawer 聚焦、Ctrl+C、窗口重绘异常
<!-- docs-section: terminal -->

使用应用内 `?` 查看实际键位：`t` 打开 Drawer，`F6`（或支持时 `Ctrl+]`）返回聚焦。远程终端或 SSH 客户端可能截获快捷键。运行 `codex-tui doctor terminal`，确认 TERM、TTY、窗口调整和子进程退出。Stable 必须拥有真实控制 TTY 的 Focus/Resize/Ctrl+C/Restore 记录，托管 PTY 不代替。

PTY 子进程从创建、初始化到分离 actor 退出始终由终止与回收守卫持有。取得 reader/writer、发布 Ready 或启动读取线程失败，不能放弃回收责任。故障注入使用本地子进程覆盖各启动阶段，不代替真实 SSH 验收。

可捕获的 Unix 进程信号（SIGTERM、SIGHUP、SIGINT）进入交互程序的正常退出路径，先恢复终端 raw 模式、备用屏幕与光标，再执行原有的有界最终保存；保存失败仍返回错误。raw 模式 Ctrl+C 按键与 OS SIGINT 分别验收。SIGKILL 与已经断开的物理终端不属于应用可保证恢复的范围；无界面子命令不安装这些交互退出处理器。

Forge 读取器把有界 8KiB 缓冲区放在堆上，避免缓冲区内嵌到多层异步状态后放大入口栈占用。小体积 future 检查与原生 Windows 调试程序 CLI 测试共同覆盖启动栈溢出；仅对交互入口使用堆分配并不足够。帮助、版本和无效参数仍无需 TTY、后端或状态写入，不扩大线程栈。

## Registry 繁忙时的看板更新
<!-- docs-section: board -->

规划 worker 同时只计算一份元数据快照。线程不超过 1 万且计算期间仅有少量会话来源变化时，使用**当前**输入重新投影最多 64 张受影响卡片（包括成员增删与共享 worktree 冲突影响），再安装结果，不直接接受旧 generation。人工编辑、本地/Forge/Git/目标/后端权威变化或更大的差异仍要求重新捕获全量快照。这避免单条高频会话无限废弃其他有效更新，但不保证任意全局事件风暴下的绝对延迟。超过 1 万线程时，若结果已经过期，UI 直接拒绝旧投影并捕获当前输入交给后台重算，不在事件循环内扫描所有卡片。`planning-ui-stale-retry-50k` 只度量 UI 的拒绝与输入捕获，不包含后台计算或真实终端延迟。保留的 5 千条持续事件夹具与性能诊断属于合成证据，不代表人工效率或多小时真实使用已认证。

## SQLite 损坏或未来 Schema 拒绝
<!-- docs-section: store -->

使用 `codex-tui doctor store` 执行明确的 SQLite 完整性扫描；交互程序启动时也会进行一次检查，但常规读写不再每次打开数据库都重复全库 quick_check。之后停止所有进程并保留数据库/WAL/SHM 和恢复镜像。不要把正在写的数据库直接复制为一致性备份，或让多个进程同时改写。 TUI 运行期间保持跨进程 SQLite 独占写者锁；如有写者，离线恢复会被拒绝。打开 SQLite 前将拒绝已存在的数据库文件或写者锁文件符号链接、非普通文件；这是私有路径防护，不代表可原子阻止同一用户的恶意进程并发替换文件。v1.4 首次安装只使用当前 SQLite v4，拒绝未部署的 v1–v3 镜像且不自动清空。

`PRAGMA quick_check(1)` 只有返回精确的 `ok` 才通过准入。即使 SQL 调用成功，只要结果行报告约束或完整性错误，健康检查仍失败：`doctor store` 以 3 退出，交互启动禁用本地写入，包括对话索引清理/写入及变更恢复线程的 Store 访问。现有数据库先通过只读连接检查，再允许配置 WAL 或初始化派生表。Store 副本共享失败准入结果，包括启动时状态解码及索引维护失败，恢复线程不能绕过已降级的界面继续写入。首次访问完成连接配置后才共享成功准入；临时配置失败可通过显式健康检查重试。首次 Store 访问和显式 Doctor 会扫描完整性；普通操作复用准入，不逐次全扫描。经验证的离线恢复完成后，需要重新通过健康检查，才允许该句柄继续访问。这不保证抵抗物理故障或检查后的独立写入。

随发行版提供的 SQLite 在只读连接中不计算 CHECK 表达式。因此，准入会在配置连接前，通过只读 `EXISTS` 查询额外校验当前 schema 的快捷槽 1–9 范围，以及 `pinned`、`manual_ready`、`adopted` 三个布尔字段的 0/1 范围。Doctor 明确将完整性范围标为 `read-only SQLite quick_check plus current application CHECK constraints`。这些查询仅在首次准入、显式健康检查和恢复镜像验证时运行；常规行解码也会拒绝越界快捷槽和布尔值，不增加扫描。

规划编辑按唯一键读取目标 WorkCard 或 ScratchWork；完整规划快照在同一读取事务中一次批读有序关联，不再为每张卡片分别查询 links。成功编辑仍在提交后返回完整快照，因此刷新成本仍随本地持久化卡片数量增长。本次修复减少不必要查询，不声称已测得适用于所有工作量的延迟上限。

## 提供最小脱敏证据
<!-- docs-section: artifacts -->

`codex-tui doctor bundle --offline --output ./codex-tui-support` 不启动 Codex App Server，仅采集本地脱敏元数据和摘要；真实账号资格须走单独授权的在线流程。分享前仍需检查内部主机名、个人路径、凭据、Prompt、原始日志和评论正文。提供最小复现命令、退出码、源码 SHA 和关联 CI Run ID，未获取的真实环境证据明确标为**尚未验证**。
