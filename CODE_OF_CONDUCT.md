# Collaboration and conduct
<!-- docs-section: overview -->

**Language / 语言:** [English](CODE_OF_CONDUCT.md) · [简体中文](CODE_OF_CONDUCT.zh-CN.md)

This project welcomes thoughtful, reproducible engineering contributions in either English or Simplified Chinese. This policy describes practical collaboration expectations; it does not invent a legal compliance program or response SLA.

## Expected behavior
<!-- docs-section: expected -->

Focus discussions on observable facts, tests and trade-offs. Assume good intent while questioning design choices. State scope and uncertainty honestly, credit contributions and links to upstream work, respect maintainers' time, and keep criticism technical rather than personal. Treat differences between GitHub public examples and internal GitLab deployments explicitly.

## Unacceptable behavior
<!-- docs-section: unacceptable -->

No harassment, discriminatory slurs, threats, doxxing, spam or unauthorized release of private communications, credentials or internal project information. Do not fabricate test results, hide failing gates, pressure others into bypassing branch protection, or present synthetic evidence as real user validation.

## Raising and resolving concerns
<!-- docs-section: escalation -->

For routine conduct concerns, ask the maintainer to review using the least public channel appropriate for the sensitivity. For vulnerability disclosures use [SECURITY.md](SECURITY.md). Maintainers may request evidence, ask for edits, restrict a discussion or close irrelevant content in line with repository moderation capabilities; there is no promise of 24/7 staffing.
